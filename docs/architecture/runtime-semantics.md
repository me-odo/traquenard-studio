# Runtime semantics

For identical artifact, initial state, private semantic seed, participants, and ordered external events, the reducer emits the same state and event sequence. `engine-core` has no IO, browser APIs, global random source, or clock. Its RNG is an HMAC-SHA-256 counter-mode deterministic generator with rejection-sampled index selection; the private secret and counter are explicit server-owned session fields. Production composition generates 256 bits of OS randomness, while internal runtime tests and the simulator may inject a fixed secret. The secret, counter, and replay material are never public protocol inputs or client projections.

The runtime advances pure operations until it reaches input/timer barriers or completion. Exhausting the root normally with no pending work is successful completion; `end` remains an explicit early or unconditional termination operation. Exactly one deterministic `execution.completed` event is emitted. Clients submit only idempotent gameplay intents; opaque participant credentials are resolved at the transport boundary and participant IDs are never accepted as caller authority. Logical-time advancement and disconnect/reconnect lifecycle are distinct trusted system inputs. Processed identities use separate typed namespaces for each participant's client commands and each kind of system input, so equal raw IDs cannot collide across authority boundaries. A retry must also carry the identical canonical semantic payload or it is rejected as an idempotency conflict. All semantically relevant client and system inputs are recorded for replay.

At the runtime level, a disconnect of any required participant globally pauses the session; trusted time advancement and gameplay commands are rejected while paused, and reconnection of all required participants resumes it without consuming paused wall time. The current WebSocket adapter does not yet produce lifecycle system inputs from real connections, and no server scheduler currently drives logical time. Those transport integrations are future work tracked in issue #3; the present contract is exercised through direct runtime inputs and deterministic tests.

Presentation events carry first-class audiences (`everyone`, `host`, one participant expression, participant list, team, role). Server projections use explicit per-event public shapes and remove whole unauthorized events, including payloads; hiding in CSS is never security.

The server-private event log records artifact identity, semantic seed, accepted inputs, logical-time advances, connection changes, random outcomes, presentations, and completion. It is sufficient for deterministic replay without pretending every function call is event sourced. Logical time and timer due points remain finite nonnegative safe integers; overflow is rejected before state mutation.
